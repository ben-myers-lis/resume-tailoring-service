## Conflicts resolved explicitly

- The older assessment pack's default of two pages is now a maximum of two, without padding.
- The older evidence-only metric wording is retained for APPLICATION. Explicitly authorized ILLUSTRATIVE runs may use visibly labeled hypothetical metrics.
- The original keyword bank's no-universal-keyword-list rule is preserved. The later breadth preference never authorizes unsupported skills or an artificial ratio.
- The latest natural-emphasis rule supersedes bold experience figures or repeated bold lead-ins.
- Account/project names in historical sources are provenance only. Runtime inputs contain the actual content instead of instructions to “use the other project.”

## New implementation choices

- Separate original facts, vocabulary/public context, generated claims, and assessment feedback.
- Use explicit candidate/profile/JD/run/revision IDs and source-origin metadata.
- Use a fresh assessment request and a bounded repair budget, with honest unresolved status.
- Keep provider API options outside the policy. The starter accepts a provider-neutral adapter and does not choose a model.
- Generate the conversation file from the same authoritative components as the application package.
- Keep structural tests separate from live semantic model evaluations. No quality-parity claim is made across accounts or models.
